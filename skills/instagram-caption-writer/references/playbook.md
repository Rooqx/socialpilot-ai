# Asset-linked Instagram caption practice

## Caption depends on the media

Before writing, classify asset state: `rendered_verified`, `rendered_needs_revision`, `brief_only`, `missing`. Only the first means the caption can truthfully describe what viewers see. A carousel storyboard isn't an image; a Reel script isn't a published video.

## Native caption architecture

1. Name the intended audience and the actual visible learning moment. For a carousel, inspect the cover and final slide; for a Reel, inspect spoken/on-screen content.
2. Write one opening sentence that contextualizes the asset rather than duplicating every word on it.
3. Add supporting details readers cannot infer from the visual, such as practical steps, why a choice matters or an important caveat.
4. Keep calls to action useful. A CTA can invite a substantive question, a save for later reference, or no action at all.
5. Add only relevant hashtags and descriptive accessibility suggestions. Verify platform-specific limits at execution when preparing real handoff.
6. If the asset is missing, deliver a labeled caption proposal alongside a visual brief—not a claim of a finished post.

## Example

Carousel cover says "3 checks before deploying your API" and shows three actual checks. Bad caption: "The secrets nobody wants you to know—swipe for the ultimate hack." Better: "These checks catch three easy-to-miss production problems: missing runtime configuration, unhealthy dependencies, and incorrect readiness signals. The slides show the checks and when to use each." Only say the slides contain them if the rendered slides do.

## Quality gate

Cross-check the caption against every asset claim, the user's actual voice, technical accuracy, alt text and visual rights. Avoid adding numerical performance results merely because an engaging caption "needs proof." Never assume hashtags or engagement tactics guarantee discoverability.
