# Seven focused editing sweeps

## Edit without erasing the author

1. **Meaning:** identify the primary promise and remove material unrelated to it.
2. **Clarity:** replace abstractions with recognizable examples; define necessary jargon once.
3. **Voice:** match observed rhythm and register, but keep intentional variation.
4. **Proof:** flag added quantifiers, numbers, universal claims and unattributed quotations.
5. **Specificity:** replace vague adjectives with facts *already supported by the source*; never invent details to make copy more exciting.
6. **Flow:** repair missing logical bridges and unnecessary rhetorical gimmicks; avoid line-break-only drama.
7. **Risk:** recheck technical accuracy, sensitive personal content, misleading implications and platform-specific constraints.

## Editing modes

**Light edit:** preserve the author's structure and intent; fix readability. **Structural edit:** reorganize sequence and transitions without changing claims. **Substantive rewrite:** requires the owner's permission when core position, tone or factual meaning changes. Choose based on the request rather than rewriting by default.

## Before/after illustration

Before: "In the ever-changing world of tech, proper configuration is important for success." After: "A deployment can compile successfully and still fail at runtime when a required environment variable is missing." The edited sentence remains a general fact, not an invented report of the user's project.

## Regression guard

Keep a claim-level diff: which fact changed, which number was preserved, and whether a new factual assertion was introduced. Send new claims back through the fact-checker. Record user-preferred revisions as suggestions to the voice profile, never permanent instructions from a single unconfirmed edit.
