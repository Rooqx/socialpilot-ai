# Honest hook experiments

## Promise–payoff contract

A hook is good only if the content immediately honors the curiosity or practical value it creates. Extract the precise result the reader will receive **before** writing alternatives. If the source is a personal claim, verify ownership of the experience; if it is a statistic, require a source or remove the number.

## Generate by meaning, not synonyms

- **Observation:** a concrete detail that changes how the audience interprets the topic.
- **Question:** a real unresolved decision with a useful answer in the post.
- **Tradeoff:** competing valid constraints, not a straw-man argument.
- **Mini-story:** setting → difficulty → lesson, with verified first-person ownership.
- **Useful preview:** the exact steps or checks a reader will actually get.
- **Evidence-led opening:** a specific figure only when the denominator and measurement are supported.

## Worked example

Underlying material: a reproducible example of a retry handler writing duplicate payments. Poor: "This simple trick 10x'd our revenue!" (unsupported and unrelated). Better: "A retry can be successful and still charge twice if the write isn't idempotent." A thread or carousel must then explain the idempotency boundary with an accurate example.

## Evaluation rubric

For each of four to six candidates, record: who it addresses, implied promise, proof required, platform fit, voice match and whether the body fulfills it. Reject hooks that require a sensational title to make ordinary content seem valuable. Select only after checking the body, not before. Never present the chosen variant as scientifically optimal without actual experiment results.
